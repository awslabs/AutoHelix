# AutoHelix Development

AutoHelix is an agent-powered iterative optimization tool. It runs AI agents in a loop — each iteration is isolated in private copies of the code, validated, and only accepted when it passes. See `README.md` for user-facing docs. For setting up training/eval (ML benchmark) cells, see `docs/ml-experiments.md`.

## Setup

Activate the virtual environment before running any commands:

```bash
source .venv/bin/activate
```

If the venv doesn't exist yet:

```bash
uv venv
source .venv/bin/activate
uv pip install -e ".[dev]"
```

## Project Layout

- `src/autohelix/harness.py` - main iteration loop (start here)
- `src/autohelix/cli.py` - CLI commands (bare `autohelix`: the entry screen; run, resume, stop, land, archive, delete, view, dashboard, wait, hint, ask, review, report)
- `src/autohelix/config.py` - configuration dataclasses and parsing
- `src/autohelix/agents/` - agent backends, one per `agent.cli` (claudecode, codex, opencode; mock for tests)
- `src/autohelix/iteration.py` - one iteration's copies: agent copy, freeze to a tree, evaluation copies, accept, notes/cleanup
- `src/autohelix/awake.py` - keeps the machine awake during a `run`/`resume` segment (`caffeinate -i -w <pid>`, `systemd-inhibit` + `tail --pid`; silent when missing; the root conftest.py replaces `awake._start` and puts stand-ins first on PATH)
- `src/autohelix/sandbox.py` - child-process environments (PYTHONPATH remap)
- `src/autohelix/checks.py` - gate, observe and stop command execution; metric gate comparison
- `src/autohelix/judge.py` / `review.py` - `autohelix ask` (yes/no) and `autohelix review` (feedback), read-only agent calls
- `src/autohelix/launcher.py` - the `autohelix` launcher put first on harness commands' PATH
- `src/autohelix/history.py` - iteration history (JSONL)
- `src/autohelix/events.py` - run events for `autohelix wait` (read-only watcher, event schema, cursor)
- `src/autohelix/runs.py` - run identity/paths and selection, ownership locks, ref recovery, landing, archive/delete, copies sweep
- `src/autohelix/workspace.py` - candidate copies (`Repo`, `Copy`, `Fingerprint`), tree snapshots, write scope and judge guard
- `src/autohelix/display.py` - live Rich display
- `src/autohelix/terminal.py` - what `run`/`resume`/bare `autohelix` print (header, rows, end block), and every screen's one warning form (`warning`/`warn`: `  ! message`) and one wrap helper (`wrap`/`hanging`/`show`: breaks at spaces only, never inside a word such as a path or branch name)
- `src/autohelix/run_status.py` - live run status (`.autohelix/runs/<id>/.internal/status.json`)
- `src/autohelix/live.py` - live terminal `view` (run table + the log the run status points at, or the running iteration's latest ask/review transcript) and `dashboard`
- `src/autohelix/viewer.py` + `viewer_resources/` - `autohelix view --web` / `dashboard --web` app (`/` run list, `/run/<id>/` one run)
- `src/autohelix/run_table.py` - `view` / `dashboard` terminal text (the `--json` payloads, `ProjectRuns.runs()` / `.run()`), and bare `autohelix`'s entry screen above its question
- `src/autohelix/menu.py` - the entry screen's arrow-key menu (`choose`) and Enter/q question (`confirm`)
- `src/autohelix/replay.py` - parse saved agent logs into events (live view, web view)
- `src/autohelix/prompt_template.py` - agent prompt rendering (built-in template, or the config's `prompt_template:` file; `.autohelix/prompt.md` is no longer read)
- `tests/` - test suite (pytest)
- `examples/` - example projects (sorting, ml-recipe, writing,
  task-queue, research, workflow-optimization, algotune, posttrain,
  kernelbench)
- `scripts/run_dev_test.sh` - quick real-agent test against a bundled example (extra flags go to `autohelix run`)
- `docs/` - user-facing documentation (plain markdown)

## CLI Commands

```
autohelix              # In a terminal: the project's runs, then an agent session with the bundled skill (ask about the runs, or set up a new experiment); else the help, exit 2
autohelix run [CONFIG] # Start a new run of autohelix.yaml (or autohelix/CONFIG.yaml) (--group NAME: share notes/code with its group; --check: only the checks before the first write)
autohelix resume [ID]  # Continue a run with its stored config (-n N more, --until N total; --group / --land change the stored ones)
autohelix stop         # End a run after its current iteration (--now: interrupt it, same host)
autohelix land         # Fast-forward the run tip onto its starting branch
autohelix archive      # Hide a run from the dashboard and a bare resume; keeps everything
autohelix delete       # Remove a run's state and ref (--force with unlanded commits)
autohelix view         # Follow a run live in the terminal; --once / --json snapshot; --web page (127.0.0.1)
autohelix dashboard    # The project's runs, live in the terminal; --once / --json; --web (same server as view)
autohelix hint         # Send a hint to the running agent (picked up next iteration)
autohelix ask          # Yes/no judgment by a read-only agent (exit 0/1/2); `ask:` gates use it
autohelix review       # Read-only review of a change (feedback + ##autohelix metrics); `review:` observe entries use it
autohelix report       # Agent-written analysis of the run
autohelix wait         # Block until a run event (iteration, start, end, crash), print it as JSON; --follow, --after CURSOR
```

## Testing

```bash
pytest -n auto            # run all fast tests in parallel (~3 min; plain `pytest` is ~11 min); CI runs this on Linux and macOS, Python 3.11, 3.12 and the newest
pytest -m slow            # run slow tests (requires real agent)
bash scripts/run_dev_test.sh              # manual test with real agent (sorting, 1 iteration)
```

## Examples Warning

**Do not commit optimized example code.** Examples should always contain the slow baseline version so users can see the optimization potential. If you run an example and it gets optimized, do NOT commit those changes to the main repo.

## Architecture Notes

- Entry points: bare `autohelix` (`cli._entry`, only when stdin and stdout are TTYs, `cli._interactive`; else the help and "Run `autohelix` in a terminal to start." on stderr, exit 2) shows the project (`cli.entry_project`: `runs.find_project`'s folder when it has runs, else the nearest folder up from here with a config, else the git top level; outside a checkout it says so, `_git_problem`, and offers nothing, exit 1): a header (`run_table.entry_header`, drawn before the runs are read), the dashboard's table (`run_table.entry_lines`, `table_lines`), one suggested command per run (`run_table.suggestion`), the archived count and the `--help` footer, then one question (`cli.entry_options`: with non-archived runs, Ask about these runs / Set up a new experiment; configs without runs: check and finish them; nothing: `entry_question`, Enter/q; `menu.choose`/`menu.confirm`, which drop keys typed before them; q or Esc raises `menu.Quit`, exit 0; Ctrl-C exits 130). Every option execs the same agent session (`_agent_argv`, Claude Code/Codex/OpenCode, never `mock`; "Which agent?" with several) with the bundled skill and `cli.first_prompt` (runs, configs, the pick, AutoHelix's CLI, Python and docs: `cli.docs_dir`, the package's `autohelix/docs` that pyproject force-includes from docs/, else the checkout's). There is no setup command. `autohelix run [NAME]` finds the config (`config.find_config`), creates `.autohelix/` on first use and starts the harness loop.
- Iteration isolation: `iteration.py` runs every phase in its own fresh `workspace.Copy` (agent, checks, each review, stop; baseline and report too): a private folder holding one tree, with its own `.git` borrowing the user's objects via alternates. The harness reads copies only from outside through `Repo` and a harness index kept in a private per-process folder; it never runs git inside a copy after a call used it. The agent copy is frozen to a tree T (pinned at `refs/autohelix-tmp/<id>`); checks run on a fresh copy of T with HEAD at A and T's files verified after every command (checks, stop and report copies are `watched`: fingerprinted for `Copy.changed()`; agent and judge copies aren't); accept commits exactly T on A (`commit-tree`, no hooks), CAS-updates `refs/autohelix/<id>`, and records history in a deferred-SIGINT section. A no-op is accepted without a commit. A rejected attempt's T (also after a failed or timed-out agent call) is kept as `refs/autohelix-rejected/<id>/<n>` (`keep_rejected`; removed by `delete`), and the next agent copy gets the latest rejection's `base..T` (`workspace.diff_args`, independent of the user's git config) as `rejected.patch` (over 2 MiB: none, the prompt's `rejected_diff` names the `git diff`). An attempt whose T equals its base keeps no ref. Run segments land separately on the target branch.
- Evaluation (`harness._evaluate`; user docs in `docs/config.md`): gate commands in list order (first failure rejects; `ask:` entries render to `autohelix ask [flags] -- Q`), then `observe:` entries top to bottom (`review:` entries render to `autohelix review [flags] -- P`); after each entry, the metric gates on its metrics, compared with the last accepted commit-creating record (`checks.metric_reference`). A failed observe entry is recorded and contributes no metrics; a missing gated metric fails. The baseline runs everything and rejects nothing; a missing command metric is a setup error. Metrics come only from `##autohelix[name=value]` lines on stdout, by name (`checks.parse_structured_metrics`). Unknown top-level keys and old config keys are errors (`config.RENAMED_TOP_LEVEL_KEYS`, `agents.RENAMED_AGENT_KEYS`, `agents.RENAMED_CLIS`, `config.RENAMED_ENTRY_AGENT_KEYS`); agent values are type-checked (`agents.agent_string`, `agents.cli_value`); `agent:` is `cli` (claude-code, codex, opencode; hidden `mock`, whose test knobs are `agent.mock:`), `model`, `effort` (both passed through), `timeout`, `extra_args`, `auto_memory`; a `prompt_template:` that doesn't parse is a config error (`prompt_template.template_problem`), one that fails to render raises naming it. `run --check` is `Harness(check_only=True)`: every refusal before the first write, then nothing. Preflight (`checks.preflight_check`) finds every agent the config runs (`Config.agent_commands`: the main agent, each `ask:`/`review:` judge, resolved like `judge.judge_config`) with `agents.command_path` (`$AUTOHELIX_CLAUDE_CODE_CMD` / `_CODEX_CMD` / `_OPENCODE_CMD`, else `claude`/`codex`/`opencode` on PATH; never the config), the backends' own resolver; bare `autohelix` starts `agents.executable`. A set `AUTOHELIX_CLAUDE_CMD` is an error (`agents.variable_problem`: preflight, `judge_config`, the entry screen). `ask`/`review` take `--cli`/`--model`/`--effort` (`cli._judge_options`; `--agent`/`--command` are hidden errors).
- Copy location: copies live outside the project, at `<base>/<dirname>-<hash8>/<run-id>/iter-N-<role>`, where base is `$AUTOHELIX_COPIES_ROOT` or `${XDG_CACHE_HOME:-~/.cache}/autohelix/copies` (`runs.copies_base()`). `runs.claim_copies()` fixes the folder for a process under the run lock (created on first use by `ensure_copies`: private 0700, owned, no symlinks below the base; a shared base must be sticky), base recorded in `runs/<id>/.internal/copies` for observers (`RunPaths.copies`), `GIT_CEILING_DIRECTORIES` set there. Segment end, standalone report and delete remove it; the project's folder stays with a `project.json` record (path, host) so `runs.sweep_copies()`, at the start of every `run`/`resume`, can remove leftovers of killed processes (runs whose lock is free) and other projects' folders whose checkout is gone (same host, over a day old). The root `conftest.py` points the base at a temporary folder for every test, examples included.
- State layout (`RunPaths`; user docs in `docs/concepts.md`): `runs/<id>/` holds what people read (`run.json`, `config.yaml`, `history.jsonl`, `hints.md`, `report.md`/`.html`, the `notes` link, `iterations/NNN/`, `logs/`); the harness's own files are in `runs/<id>/.internal/` (`status.json`, `segments.jsonl` (the run's event log: a start record, an iteration record per final record, an end record per segment), `stop.json` (`autohelix stop`'s request), `usage/NNN.jsonl`, `copies`, `notes/<N>/`, `attempts/`, `report.json`, ...) and `.autohelix/.internal/` (`locks/<id>.lock`, `locks/selection.lock`, `bin/`). Iteration folders are three digits (`000` the baseline): `record.json` (derived: every record write goes through `history.write_records`, which rewrites it last; present = folder complete), `prompt.md`, `agent.log`, `notes` (link to the version saved with it), `gates/<k>/` and `stop/<k>/` (1-based position in `gates:`/`stop:`, only for commands that ran: `command.txt`, `stdout.txt`/`stderr.txt` capped 64 KB head + 1 MB tail, `ask*.log`), `observe/<name>/` (uncapped stdout, stderr, captures, `review*.log`), `rejected.patch`. A reused number (killed iteration, baseline retry) first moves the old folder to `.internal/attempts/NNN-<k>/` (`History.supersede`). Each command runs in a call folder named after where its output goes (`iter-N-gates-2`, `iter-N-observe-<name>`, `iter-N-stop-1` in the copies folder; `$AUTOHELIX_CALL` = `gates/2`, ...). Its output is staged there after the command ended, then replaces its stored folder; `$AUTOHELIX_LOG_DIR` is the call folder's private `logs/`, from which only regular single-link `ask*.log`/`review*.log` move into the staged output. A judge's usage record names its transcript at call time by destination, `{"call": "gates/2", "log": "ask.log"}`, never rewritten: `RunPaths.usage_log` resolves it (stored if it's there, else the live call folder); a baseline retry appends a `{"superseded": "000-1"}` marker and `usage_log.read_usage` gives the records before it that `attempt` (other tools' records keep a `log` path). Logs named by untrusted metadata open only via `safe_open.open_run_log` (`RunPaths.relative_log`; with `running`, also the running iteration's live `<copies>/iter-N-<call>/logs/` transcripts, `RunPaths.live_transcript`), for viewer and `view` alike.
- Copy layout: nothing in a copy looks like project state. Agent copies get the harness's material in `<copy>/.autohelix-iteration/` (`workspace.ITERATION_DIR`), mirroring the run folder: `prompt.md` (the rendered prompt), `notes/`, `history.jsonl`, `hints.md`, `iterations/NNN/` for the last 5 iterations plus the last accepted one (`iteration.seeded_iterations`: `record.json`, failing gates' `gates/<k>/`, `observe/`, `stop/`; no `agent.log`, `prompt.md`, `notes` link, passing gates or `rejected.patch`), `runtime/state/`, `rejected.patch` (after a rejection), `commit_summary.txt` (written by the agent), and `runs/<id>/` for the imported run (`run --import`) and other runs of the group (`run.json`, `history.jsonl`, `notes/`); with either, the prompt's reading list becomes a "Where things are" block saying which material is the run's own (editable notes), which run is imported and which are group members (read-only). Checks copies get only `candidate.diff` (the complete change, new files included); a judge's own copy (made by `autohelix ask`/`review` in `$AUTOHELIX_SCRATCH`) `candidate.diff` (`--binary`) and, for `review --previous`, `previous.md`; stop copies get none of it. `$AUTOHELIX_PREVIOUS` (`observe/<name>/` of the last accepted iteration where the entry succeeded) and `$AUTOHELIX_OBSERVATIONS` (the accepted iteration's `observe/`) are per-call copies. A copy's `.git` lists branches, tags, remotes and only this run's ref plus its imported run's and its group's (`Copy.create(refs=...)`); other runs' commits are reachable by hash, not discoverable.
- Scope enforcement: `Copy.snapshot()` resets out-of-scope paths to A's entries in the harness index only (nothing is written into the copy), with `--attr-source=A` when git supports it. `.autohelix/` and `.autohelix-iteration/` are excluded from `add -A` by pathspec (unless already ignored: git refuses an exclude naming an ignored folder), so their contents are never hashed into the user's object store. Submodule changes reject the iteration.
- Notes persist across rejections: freezing (or closing) the agent copy saves `notes/` as a new version, `runs/<id>/.internal/notes/<iteration>/` (`7-2` for a second save of 7; each a plain copy), then swaps the `runs/<id>/notes` symlink and the iteration's `iterations/NNN/notes` link to it by rename (`iteration.save_notes()`; deletions honoured, all versions kept; a pre-version real `notes/` folder becomes `.internal/notes/old`). `notes/` is the sole agent-owned region and the only thing that round-trips; `iteration.prepare_state()` seeds agent copies with `notes/` plus read-only reference.
- Run identity: `RunPaths` is the authority for state layout. Ids are `YYYYMMDD-HHMM-[name-]xxxx`; the suffix is unique across the repo's run refs and every command accepts it (`runs.resolve_run`). Runs have no lifecycle state, only an `archived` flag. `run` always creates (`select_run(new=True)`, warnings only); `resume` takes an id, else a config name (`resume perf`), else the default config, and continues that config's most recently active non-archived run, preferring runs with a baseline (`cli._resume_target`; with nothing to run, `--land`/`--group` are stored at once, `runs.set_options`). There is no current-run pointer: `land`, `hint`, `view`, `report` without an id take `runs.default_run` (the one running run, else the most recently active non-archived one; several running refuse), named on stderr (`cli._chosen_run`). Commands that read runs find the project from a subfolder (`runs.find_project`, `cli._project`); multi-id commands resolve every id first (`runs.resolve_runs`, `cli._each_run`). The viewer serves run data only under `/api/run/<id>/` (`RunData` needs an id). A new run is named after the config file's stem (`runs.new_run_name`; no `name:` key, no `run --name`); the config path in `run.json` is the source file (naming, `run_command`, a bare `resume`'s selection, messages; there is no `-c`). All writing operations hold the per-run process lock. Whether a run is running comes from that lock: a running status (or open segment) on this host whose lock is free, or held by this process under another pid, reads as crashed (`run_status.holder_gone`, used by `read_run_status` and `wait`; `runs.is_live` probes read-only and creates no lock file). A run folder without its stored config/template (a development build's) is refused (`runs.development_run`). Legacy top-level histories are refused for writes; no migration is attempted.
- One config per run: `select_run` stores `runs/<id>/config.yaml` at creation (the file's text verbatim) and, with a `prompt_template:`, its text as `runs/<id>/prompt_template.md` (`RunPaths.template`). Every reader loads that copy (`runs.load_run_config`: `source=` the file it came from, `template_text=` the stored template, which `Config.prompt_template_text` carries): segments, `view`, `dashboard`, `report`, the viewer (which also shows the stored template), judges' `$AUTOHELIX_CONFIG`. `Harness.config_file` is the source file. `Harness._run_config` refuses an existing run before anything is spent when the file's parsed config differs (`config_changes`: the `Config` fields the harness uses, plus the template texts; other spellings of a value aren't changes), naming the settings and `run --import`; a deleted file or template continues (dim note); a run without `config.yaml`, or without its stored template, refuses; a run `select_run` just created isn't compared. Both stored files are 0444. The config and template files are always frozen, as named and resolved (`Config.protected`; `frozen_names()` shown, `frozen_patterns()` matched, glob-escaped).
- Read-only evaluation: gate, observe and stop commands, reviews and `ask` must not change candidate files. A gate or observe command's change rejects (checks copy verified after every command; the command's gate item or observe record is marked failed). Stop commands run after acceptance: the acceptance stays, the change is an error (`AutoHelixRunError`). Each stop command that ran is recorded in the record's `stops` (`checks.StopCheckResult.record`: outcome stop/continue/error, return code, `timed_out` as a flag, as gate items have it), shown as a note under the row (`terminal.Table._notes`) and in the viewer. `ask` and `review` judge the same target (`judge.judged`): in a run their own fresh copy of `$AUTOHELIX_CANDIDATE` in its own folder of `$AUTOHELIX_SCRATCH` (`candidate_target`; never the checks copy, where commands leave files and run candidate code), with `candidate.diff` named in the prompt (`describe_change`); by hand the current directory and its working-tree diff (`checkout_target`). One write guard (`DirectoryGuard`, git's listing of the judged directory, a walk outside a repository) around each call: a change fails the call (no retry, nothing sticky). Codex judges get `-c project_doc_max_bytes=0` (no AGENTS.md; unconfirmed against a real Codex). Ordinary review failures are recorded and continue; scripts own `ask` exit codes.
- Launcher: harness commands run with PYTHONPATH remapped to the copy, so `iteration.call_folder()` writes `bin/autohelix` (`launcher.py`: the harness's interpreter with `-I`, its own package first on sys.path) and puts it first on PATH; candidate code can't replace modules inside `ask`/`review`. Each command also gets `AUTOHELIX_CANDIDATE` (T as a tree), `AUTOHELIX_BASE` (A), `AUTOHELIX_PROJECT`, `AUTOHELIX_SCRATCH`, stdin `/dev/null` (`checks._execute`), and runs in its own process group, killed whole when it ends. The main agent gets neither `AUTOHELIX_PROJECT` nor `AUTOHELIX_RUN_DIR` (`run_agent`'s `deadline_env` unsets them; it gets `AUTOHELIX_RUN_ID`, `AUTOHELIX_ITERATION`), and its copy has the config file and template removed (`IterationWorkspace.agent_copy(hidden=Config.protected)`, never through a symlink; frozen, so `snapshot` resets them, and a still-absent one isn't reported as discarded): hygiene, not a boundary.
- Exit codes (`cli._segment`, `Harness.run`'s return): `run`/`resume` exit 0 for a polite end (budget, `stop:`, `autohelix stop`), 1 for errors (refused start incl. preflight on resume and no run to resume, the agent failing 3 times, a failed auto landing: `Harness.run` raises an `autohelix_reported` `AutoHelixRunError` after the ending), 130 when interrupted (`run` returns "interrupted" for one in the loop; one in the baseline/summary propagates; `cli._interruptible` maps Ctrl-C anywhere in `run`/`resume`, Harness init and preflight too). `ask`/`review`/`wait` keep their own codes. Documented in docs/cli.md#exit-codes.
- Recovery/accounting: under ownership, repair only a torn unterminated final history record and recover published commits from run/iteration trailers. Each attempted main-agent failure (an unsuccessful or timed-out call) records a rejected, unchecked iteration (`agent_error`), consumes its number, and the loop continues; `harness.MAX_CONSECUTIVE_AGENT_FAILURES` (3) in a row within a segment stop the run (stop reason kind `agent`). Failures before the call (copy, prompt) do not consume the number and stop the run with an error. Baseline retries remain iteration 0 and retain earlier call charges. Calls with unavailable usage remain unknown. Codex calls are priced (`agents/codex_cost.estimate_cost`) from the model Codex's JSON output names, else `agent.model`, else unavailable ("set agent.model"); no session files, no `extra_args` guessing. A timed-out OpenCode call has an error and an unknown cost (its finished steps' as `partial_cost_usd`).
- Resume/landing: `resume` only continues the same run (stored config, own tip): a target branch past the run's tip (`runs.target_ahead`) refuses an auto-landing resume before anything is written (`Harness.__init__`, again under the lock in `runs.reconcile`, which no longer fast-forwards the run onto it) and is a warning in manual mode; a resume after a `stop:` condition says it continues (`cli._stopped_note`). Only initial baseline capture requires a clean checkout. After baseline, gates/observe/stop/report use run candidate copies. Auto landing runs before report, with a finally fallback preserving original errors. The pin is deleted at every segment end. Archive retains evidence and unlanded refs; delete removes state/ref while persistent lock files remain outside the deleted directory.
- Groups: `run --group NAME` (stored in `run.json`; `resume --group NAME|''` changes it) makes runs of the same project share notes and code. Members are the other non-archived runs with that group (`runs.group_members()`), taken once per iteration (`IterationWorkspace.members`): copied into the copy (not linked) and listed in the prompt (`prompt_template.describe_member()`); their refs go into the copy's `.git`. No group commands: budgets, resume, land, archive stay per run. Landing mode is per run, recorded in `run.json` at creation (`--land`; else `manual` with `--group`; else `auto`; `land:`/`report:` are config errors naming `--land`/`--no-report`, like `budget:`), kept on resume, changed by `resume --land`. The "also running for this config" warning is quiet for group runs and when either run lands manually.
- Import: `run --import ID` records `import: {run}` in `run.json` (with `--why`: `why`; `archive --why`: `archive_why`, kept by `--undo`). Each iteration `IterationWorkspace.imported` (`runs.imported_run`, None when unreadable) is shown like a member (`others`: copied into `runs/<id>/`, its ref in the copy's `.git`; dropped from `members` if also in the group) and as the prompt's `imported`; at the baseline, `_observe` takes `$AUTOHELIX_PREVIOUS` from the imported run's history by entry name. Not imported: budgets, metric reference, group, notes (the new run's start empty). Harness git calls on the user's repo (`Repo.git`, `runs.git`) retry briefly on lock contention (`workspace.run_git`).
- Time limits: `agent.timeout` (a duration; replaces `agent.timeout_seconds` and `budget.iteration_time`, which are now config errors) is always a hard kill of the main agent, and also gives time-left hints where the CLI supports them: Claude Code hooks (`PostToolUse`/`UserPromptSubmit`), the same hook for Codex CLIs that support it (`_check_codex_time_left`: an older one warns and runs without), an OpenCode plugin; all via `$AUTOHELIX_TIME_LEFT_SCRIPT` (`<project>/.autohelix/.internal/bin/time_left.sh`, copied from `src/autohelix/bin/` at run start). `ask:`/`review:` entries don't use it: the entry's `timeout:` is the command's deadline and the judge's `--timeout` (an `ask:` entry's defaults to 10m, `config.ASK_TIMEOUT`; an entry `agent.timeout` is an error). See `harness.py:_install_time_left()`.
- Budgets are per segment (one `run`/`resume` command; a `Harness` runs one segment, a second `run()` raises), on the command line (`budget:` is a config error naming the flags): `run`/`resume` `-n` / `--until` / `--cost` / `--time` make a `harness.Budget` (`Harness.run(budget)`; library callers and tests pass one too). `Budget.last_iteration(done)`: `--until`, else done + `-n`, else no cap with only cost/time, else done + `DEFAULT_ITERATIONS` (1: a bare `run` is one checked attempt). `--cost` counts what this segment charged (the baseline's from the history, then each iteration's `result.cost`), `--time` its monotonic wall clock (baseline included); both checked before and after each iteration (never interrupting one). `status.json` records the caps: `max_iterations` (None: no cap) and `max_cost_usd` = cost before + `--cost` as run totals, `max_time_seconds` as this segment's own `--time` (never a run total) with `segment_started_at`, the wall-clock time its `--time` counts from; the viewer's `progress` and `view`/`dashboard` read them from there, never from the config (`run_table.time_cap`, `dashboard.js timeCap`, viewer.js's Budget chip, all formatting with `iteration_time.format_duration`'s 1h30m: only while running, "12m5s of 1h (this segment)", the dashboard row short "12m5s/1h", "(time up)" past the cap; the run's total time has no cap). `runs/<id>/.internal/segments.jsonl` (`run_status.SegmentLog`, `read_segments`, `RunPaths.segments`) is append-only: a start record written with the status at the top of `_run`, before its checks (ensure_runtime_ignored, require_clean, preflight: a refused start is a failed segment that lands nothing, `_segment_checked`), an iteration record (`SegmentLog.iteration`, `events.iteration_fields`: the `iteration` event's fields) each time a record is final (after `workspace.record` wrote it, in `run_iteration`'s finally, after stop commands; `_write_baseline`, a failed baseline too; a record no line reports, its process killed in between or `reconcile` recovering it, is logged for the last segment before the next start, `SegmentLog.catch_up`), an end record (state, stop reason, iterations added, last iteration, error) in `run()`'s finally, linked by `segment`; one O_APPEND write + fsync each, never rewritten; `read_segments` pairs start and end and marks a start without an end `open`. `autohelix wait` (`events.Watcher`) is a pure reader of that one log per run (read on from where it ended; opened via `safe_open.open_file`: regular file, no symlinks, `LOG_CAP`), nothing written; its events are the log's lines in order plus `crashed` (an open segment followed by another's start, or whose process is gone, `holder_gone`, on a reread; once confirmed not probed again until the log grows); its cursor is per run `[lines reported, last segment reported crashed]` (`Marks`; never times; a crash is pending until its segment is marked, so lines appended after it don't report it again); a run without segments is `new`. `RunLock` retries for a moment (`runs.LOCK_RETRIES`) so an `is_live` probe of a free lock doesn't refuse a resume. The status carries the segment's number (`segment`, `SegmentLog.next_number()` before `run_status.start`). `autohelix stop` (`cli._stop_run`) writes `runs/<id>/.internal/stop.json` (`run_status.write_stop_request`: `requested_at`, `why`, `now`, `segment` from the status, `host`, `pid`), only while the status says running (`read_run_status`: its lock held) with a segment number; `_run` honours only a request for its own segment (`Harness._requested_stop`) at the top of each loop pass (first right after the baseline; never during an iteration), ending like a budget (stop reason kind `request`). `--now` also sends SIGTERM to the status's pid (same host, `ps` says autohelix), after writing the request: a background run a script started ignores SIGINT, and `Harness.run` takes SIGTERM as Ctrl-C (`_terminate_interrupts`, over the default action only; `runs.critical_section` defers both); the interrupt path notes it as the stop reason (`_note_interrupt_request`; state stays interrupted). A stale request is removed at segment start (before the status says running), the request at segment end; the viewer's run row shows it as `stop_requested` (`run_status.pending_stop`). With `--cost` the only bound, an unknown charge stops the segment only while none of its charges was priced (`priced`: a backend that can't price; else it warns). The run summary (`Harness._summary`, after the loop and landing) is skipped after an `agent` stop; its failure or Ctrl-C prints a line and leaves the segment's outcome; each call's usage goes to `.internal/usage/summary.jsonl` (`RunPaths.summary_usage`), counted by `History.cost_usages` and the viewer's totals. A flagless `resume` after an interrupted/crashed status without a `stop_reason` prints what it had left (`cli._interrupted_note`); `resume --until N` at or past N exits 0 before anything is written (`cli._last_iteration`, via `planned_run`).

## Gotchas

- **Editable install:** the package is installed with `pip install -e .`, so edits under `src/autohelix/` are live immediately — no reinstall needed. Only re-run `pip install -e .` if `pyproject.toml` dependencies or console-script entry points change.
- **Agent edits the main repo instead of its copy:** iterations run in private copies, but if an editable install (`.pth`) or a hardcoded absolute path resolves imports/writes back to the *main* repo, AutoHelix logs a best-effort warning about tracked main-checkout changes. This inspection cannot abort validation and does not revert user files. Keep per-iteration writable paths inside the copy, and put long-lived outputs (models, large artifacts) at a fixed absolute path *outside* the repo entirely.
- **Starting a fresh experiment:** every `autohelix run` creates new state and baseline; `resume` continues one. `archive`/`delete` leave code and external outputs intact. Roll code back with git and remove external outputs separately when that is your intended reset. First baseline capture needs no uncommitted changes to tracked files (untracked files are ignored, so the config needn't be committed); scripts its commands use must be committed, since copies are made from the commit. Commit the config (and those scripts) before the first `run` anyway: with auto landing, a commit made on the branch afterwards makes `resume` refuse (the branch is past the run's tip), leaving `run --import` or `resume --land manual`.
